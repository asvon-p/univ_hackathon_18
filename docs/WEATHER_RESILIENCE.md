# 간헐적인 기온 조회 실패 대응

2026-11-16. DB 마이그레이션 없이 날씨 어댑터와 화면을 개선한다.

- 날씨는 AI 공용 실행기와 분리한 전용 실행기에서 처리한다. 서로 다른 위치의 외부 조회는 프로세스당 최대 4개이며, 초과 요청은 대기열을 늘리지 않고 최근 값 또는 503으로 응답한다.
- 같은 반올림 좌표의 진행 중 요청은 Future 하나를 공유한다. 로컬·멘토처럼 서로 다른 프로세스 간에는 메모리 캐시를 공유하지 않는다.
- 최초 요청의 마감 시각을 모든 참여자가 공유한다. 전체 HTTP 제한에서 asyncio 취소로 연결을 닫으며, 아직 시작하지 않은 Future는 취소한다. 늦은 결과는 캐시에 게시하지 않는다. 종료된 작업은 진행 목록에서 제거한다.
- 동기 확장 코드처럼 취소에 응하지 않는 작업은 Python에서 강제 종료하지 않는다. 실제 종료 전까지 최대 4개 접수 한도를 차지하도록 유지해 작업 누적을 막는다.
- 성공 값은 기본 5분 캐시한다. 실패 시 동일 위치에서 최근 30분 이내 조회한 값만 `is_stale=true`, `is_fallback=true`로 제공한다. 관측 시각도 2시간 이내여야 한다. 다른 위치 값으로 대체하지 않는다.
- 실패한 위치는 3초간 재호출을 억제한다. 원 좌표, 공급자의 오류 본문, 자격증명은 로그에 남기지 않는다.
- `WEATHER_STALE_MAX_AGE_SEC` 기본값은 1800초이며 0이면 최근 값 대체를 끈다. 실제 `.env` 파일은 작업 중 읽거나 수정하지 않는다.

응답에는 기존 필드에 더해 `is_stale`, `age_seconds`, `retry_after_sec`, `notice`를 추가한다. 기존 `fetched_at`, `weather_time`은 원래 시각을 보존한다. 사용할 최근 값이 없으면 503 `WEATHER_UNAVAILABLE`, `Retry-After: 3`을 반환한다.

홈과 추천 조건 화면은 최근 값이라는 안내와 확인 시각을 표시한다. 홈의 ‘기온 다시 조회’는 날씨만 갱신하며 추천 생성·GPT 호출을 하지 않는다. 실패하거나 로그인 만료 시 안내한다. 계절·월 평균 추천으로 이동하는 링크도 제공한다.

검증 범위: AI 작업 8개 점유 중 날씨 성공, 동일 위치 20개 동시 조회 단일 호출, 서로 다른 위치 접수 상한, HTTP 취소와 작업 정리, 늦은 결과 차단, 최근 값 범위·위치 분리·재시도 복구, 실제 PostgreSQL 저장·접근 차단 및 두 계정의 동시 HTTP 요청.

## 검증 결과

- 관련 회귀 테스트 56개 통과. API·E2E는 실제 PostgreSQL 임시 스키마에서 실행했으며 테스트 종료 후 정리했다. Ruff와 변경 파일 공백 검사 통과.
- 테스트 브라우저에서 최근 기온 표시 → 재시도 후 정상 복구 → 계절·월 선택 → 추천 결과 표시를 확인했다.
- 로컬 3000/8002와 멘토 3001/8003 서버에 반영했다. 공개 HTTPS 인증 요청에서 실제 기온 조회 200(약 0.5초), 재조회 캐시 응답, 홈·계절 선택 화면 200을 확인했다.
- 검증 도중 외부 공급자에 대한 동기·비동기 연결 시간 초과가 별도로 발생했고 이후 정상화됐다. 외부 네트워크 장애 자체를 제거하는 변경은 아니다. 최근 기온도 없을 때는 명시적으로 재시도 또는 계절·월 대체를 안내한다.
- 비로그인 날씨 요청 401, 소스 파일 경로 404 유지. 기존 DB 23개 테이블과 파일 846개 해시가 변경 전후 동일했다. 계정 35개, 의류 378개를 보존했다.
- 실제 `.env`는 읽거나 수정하지 않았다. 운영 검증용 임시 인증 토큰은 사용자 승인 후 메모리에서만 2분 유효기간으로 사용했으며 로그·파일에 저장하지 않았다.
