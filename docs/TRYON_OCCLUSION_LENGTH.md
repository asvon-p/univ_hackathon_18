# 착샷 가림·바지 길이 보정 (2026-11-16)

## 원인과 변경

기존 착샷은 하의 → 상의 → 아우터 순서였지만, 순서만으로 가림 관계가 보장되지는 않았다.
마스크 없이 생성하면 원래 입고 있던 반바지의 형태나 상의 무늬가 다음 결과에 남을 수 있었다.
아우터 뒤에 안쪽 옷을 복원하는 색상 연결 영역이 넓어지면 무늬가 아우터 패널 위까지 복사될 수도 있었다.
상체만 편집하는 마스크는 긴 아우터가 하체를 덮는 경우에도 적합하지 않았다.

- `/garments/{id}/layer-image`의 비공개 PNG에 착용 역할, 바지 길이, 아우터 길이 힌트를 넣는다. DB의 의류 ID·속성·원본 파일은 바꾸지 않는다.
- 길이는 명시적인 형태명과 누끼의 실제 세로/가로 비율을 이용해 추정한다. 사진 프레임 비율을 사용하지 않는다. `shorts`는 짧은 바지로, `long pants`는 긴바지로 취급한다. 크롭·치마 등 애매한 유형은 길이 검증 대상으로 단정하지 않는다.
- 바지와 아우터는 FASHN의 마스크 기반 생성(`segmentation_free=False`)을 사용한다. 롱코트·롱패딩은 상하체 편집을 위한 `one-pieces` 내부 모드로 생성한다. 사용자 의류 분류는 여전히 아우터다.
- 바지를 생성한 직후 양쪽 엉덩이·무릎·발목 위치와 바지 분할 영역을 비교한다. 긴바지는 양쪽 다리 길이의 80% 이상, 짧은 바지는 68% 이하를 기준으로 확인한다. 불일치는 시드·스텝을 바꿔 한 번만 재시도하고, 다시 불일치하면 `GARMENT_LENGTH_MISMATCH`로 중단한다. 후속 의류 생성·잘못된 결과 저장을 진행하지 않고 접수 슬롯을 해제한다.
- 뒤에 상의를 입혀도 완성된 바지가 짧아지지 않도록 편집 범위 밖의 이전 결과를 보존한다.
- 아우터는 생성된 원단 경계와 제품의 열린 영역을 함께 사용한다. 연결된 밝은 무늬가 옆으로 퍼지는 범위를 제한하고, 연속된 실제 열린 경계에서는 상의·바지를 복원한다. 열린 영역이 끝나면 원단의 변형도 부드럽게 줄인다.
- 닫힌 긴 아우터의 원단에는 바지를 보여 주기 위한 직사각형 구멍을 만들지 않는다. 열린 영역과 생성 경계를 모두 확인하지 못하면 실제 생성된 원단의 가림을 유지하고, 화면에 안쪽 옷이 더 가려질 수 있음을 안내한다. 짧은 아우터 아래의 노출된 상의 밑단은 보존한다.
- 렌더 버전은 `occlusion-length-v5`다. 과거 결과는 기록에 남지만 새 요청의 캐시로 재사용하지 않는다. 개선 결과는 착샷을 새로 생성해서 확인한다.

## 검증

- 가림·포즈 길이·마스크 선택·재시도 파이프라인 테스트: 33개 통과.
- 실제 PostgreSQL 기반 API/화면 HTTP 테스트와 관련 단위 테스트: 76개 통과. 저장 버전, 소유권, 개인/테스트 옷장 분리, 실패 시 저장 방지 포함. 테스트 전용 스키마를 사용했다.
- GPU 작업 큐·동시 접수·예상 시간·길이 오류 슬롯 해제 테스트: 18개 통과. 이 묶음은 모델을 대체한 작업자 경계 테스트다.
- 실제 GPU 추론: 합성 반바지 인물 → 긴 청바지, 프린트 상의 위 열린 셔츠, 롱코트, 롱패딩, 니트 이후 바지 보존. 긴바지 검증에서 양쪽 다리 커버리지 1.0/0.975 확인. 최종 정상 생성은 예시별 약 8~9초/단계였다(대기·업로드·DB 저장 시간 제외).
- 실제 브라우저: 별도 임시 계정에서 하의 → 상의 → 롱코트 생성, 모달 표시, 새로고침 후 동일 결과 재조회. 실제 GPU 및 PostgreSQL 사용, 결과 1개 저장, 비로그인 이미지 접근 차단 확인 후 해당 테스트 스키마 정리.
- 로컬·멘토 서버/GPU에 적용. 공개 HTTPS 정상 응답, 소스 URL 차단 유지. 기존 35개 계정·368벌 의류 및 보관 파일 해시 보존 확인.
- `.env`는 직접·간접 모두 차단했다. 사용자 사진을 테스트에 사용하지 않았다. 합성 fixture와 로그는 Git에서 제외된 `.demo/occlusion-length/`에 보관한다.

## 한계

이 처리는 2D 생성 모델과 분할 마스크에 의한 보정이며, 실제 3D 의복 시뮬레이션이 아니다.
안감·옷깃·지퍼·유사 색상, 잘린 의류 사진, 넓은 바지나 접힌 옷에서는 길이/열린 영역 추정이 틀릴 수 있다.
포즈가 충분히 검출되지 않은 결과는 `unverified`로 기록하며 검증 성공으로 표시하지 않는다.
롱패딩 실험 중 자동 열린 영역을 확인하지 못한 사례는 닫힌 형태를 유지했다. 앞을 항상 열어 주는 품질까지 보장하지 않는다.
이 경우 옷 상세의 `누끼 정제·아우터 안쪽 설정`에서 실제 열린 영역을 확인하거나 사진을 바꾸어야 한다.

## 재검증 명령

`.env`를 읽지 않도록 PowerShell에서 설정한다. 아래 DB는 프로젝트에서 사용하던 테스트 DB이며 테스트는 별도 스키마에서 실행한다.

```powershell
$env:FITJANG_SKIP_DOTENV = '1'
$env:TEST_POSTGRES = '1'
$env:TEST_DATABASE_URL = 'postgresql+psycopg://fitjang:fitjang@127.0.0.1:5432/fitjang_test'
python -m pytest backend/tests/api/test_admin_layers.py backend/tests/api/test_tryon_results.py backend/tests/api/test_tryon_wardrobes.py backend/tests/test_garment_shape.py backend/tests/test_tryon_frontend.py backend/tests/e2e/test_tryon_wardrobes.py -o addopts='' -q
python -m pytest backend/tests/test_gpu_queue_api.py backend/tests/test_fair_tryon_queue.py backend/tests/test_tryon_timing.py -o addopts='' -q
& '.demo/tryon-runtime/venv/Scripts/python.exe' -m pytest tryon_server/tests -o addopts='' -q
```

## 합성 자산 출처

새 인물과 롱패딩은 내장 이미지 생성 도구로 생성했다. 실제 인물 사진을 참조하지 않았다.
생성 프롬프트 원문과 저장 경로는 `.demo/occlusion-length/ASSETS.md`에 기록한다.
기존 합성 의류 제품 사진도 테스트에 사용했으며 운영 옷장에는 추가하거나 교체하지 않았다.
