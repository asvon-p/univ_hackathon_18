# 착샷 예상 시간과 아우터 합성 진단

> 후속 구현 완료: [상의 보존 실험·구현·검증](TRYON_LAYERING.md).
> 아래 아우터 원인 부분은 이전 화면을 바탕으로 한 초기 판단입니다. 실제 제품 사진 확인 결과
> 기존 봄버는 닫힌 사진이 아니라 **열린 지퍼 사이로 어두운 안감이 보이는 사진**이었습니다.
> 현재는 `0015`와 `inner-preserve-v1` 보존 처리를 적용했고, 아래 `0014` 및 500개 테스트는 이전 기록입니다.

## 실제 GPU 기준 예상 시간

기존 화면의 한 벌당 40초 고정값을 제거했습니다. GPU worker가 의류 감지·전처리·추론·결과 인코딩을
포함한 처리 시간을 측정합니다. 최근 40개 표본의 가중 평균과 변동 폭으로 예상 범위를 계산합니다.
의류 유형·입력 사진 유형·추론 step 수·segmentation 설정별로 구분하고, 같은 추론 설정의
다른 의류 유형 기록은 해당 유형의 첫 측정이 생길 때까지만 보조로 사용합니다.

- **시작까지**: 현재 GPU 작업의 남은 처리 시간과 내 차례 앞의 작업을 반영합니다.
- **코디 완성까지**: 내 남은 의류뿐 아니라 다른 사용자의 남은 의류와 사용자별 순환 순서를
  함께 시뮬레이션합니다. 단계 사이에는 프론트 폴링 간격 2초의 전달 여유를 반영합니다.
- 대기·처리 상태를 2초마다 다시 조회합니다. 새 사용자 접수·취소 때문에 예상 시간이 달라질 수 있습니다.
- 처음 기록이 없으면 **예상 시간 계산 중**, 표본이 5개 미만이면 **초기 예상**으로 표시합니다.
  무조건 0초/5초를 반복하는 카운트다운을 표시하지 않습니다.
- 실행 중 작업이 측정 범위를 넘으면 지연 안내를 표시합니다. GPU 추론 뒤 결과를 전송·저장하는
  동안은 **완성된 착샷 정리 중**으로 구분합니다.

`TRYON_TIMING_FILE`은 로컬 실행기가 `.demo/tryon-runtime/timing-v1.json`으로 설정합니다.
저장되는 항목은 GPU/모델 버전 표식, 추론 설정, 처리 시간뿐입니다. 사진·얼굴 정보·계정 ID·
작업 ID·토큰은 기록하지 않습니다. GPU 또는 모델 가중치가 바뀌면 이전 표본을 사용하지 않습니다.
파일을 읽을 수 없거나 손상되면 메모리에서 새로 측정합니다. DB 스키마는 `0014`를 유지합니다.

내부 GPU 상태 응답의 `eta`는 `wait_seconds`, `remaining_seconds`,
`remaining_low_seconds`, `remaining_high_seconds`, `step_seconds`, `step_elapsed_seconds`,
`sample_count`, `basis`, `overdue`를 제공합니다. 프론트는 본인 작업 인증 후 이 숫자만 전달하며
다른 사용자나 대기열의 작업 ID를 노출하지 않습니다. 완료 결과 보관 정책은 바뀌지 않습니다.

이는 현재 접수와 측정값에 따른 예측이며 보장 시간이 아닙니다. 실제 사용자 네트워크 전송,
아직 GPU에 전달되지 않은 새 접수, 모델 부하 변화 때문에 달라질 수 있습니다.

## 상의가 아우터에 가려지는 현상

제공된 화면의 코디는 올리브 봄버 재킷·아이보리 케이블 니트·블루 데님입니다.
출력에서는 재킷이 넓게 덮이고 아이보리 니트가 거의 보이지 않습니다.
얼굴 식별이나 신체 특성 분석 없이 의류 영역과 코드만 검토했습니다.

확인된 구현은 다음과 같습니다.

1. `frontend/avatar_preview.py`는 이미 **하의 → 상의 → 아우터** 순서로 실행합니다.
2. 각 단계는 직전 결과 이미지를 사람 입력으로 사용합니다. 즉 니트를 입힌 결과에 재킷을 적용합니다.
3. `frontend/connect/tryon.py`는 상의와 아우터를 모두 `tops`로 전달합니다.
4. GPU 모델은 한 번에 사람 이미지 1장과 의류 이미지 1장을 받습니다. 마지막 재킷 단계에는
   니트 원본 이미지를 별도 조건으로 함께 주지 않습니다.
5. 현재 래퍼/모델 호출에는 재킷 앞섶을 열거나 안쪽 니트 영역을 반드시 보존하는 별도 인자가 없습니다.
   실제 3D 메시나 의류 물리 시뮬레이션은 이 경로에서 사용하지 않습니다.

따라서 **닫힌 형태의 재킷 입력과 상체를 다시 합성하는 과정이 함께 영향을 준 것**으로 판단합니다.
순서가 뒤집혀 생긴 오류는 아닙니다. 원본 재킷이 몸통을 덮는 형태인 것은 자연스러운 가림을 유도하고,
마지막 상체 합성은 보이는 안쪽 의류의 색·형태도 바꿀 수 있습니다. 어느 요인의 영향이 더 큰지는
사용자 사진을 재실험하지 않았으므로 현재 자료만으로 수치화하거나 단정하지 않습니다.

[FASHN 공식 코드](https://github.com/fashn-AI/fashn-vton-1.5)는 `tops/bottoms/one-pieces` 유형을
사용합니다. [공식 연구 설명](https://fashn.ai/research/vton-1-5)은 이미 재킷을 입은 사진에서
안쪽 상의를 바꾸는 예를 보여주지만, 모든 재킷을 열어 입히거나 두 의류를 동시에 정확히 보존한다고
보장하지 않습니다. 현재 `segmentation_free=True`를 단순히 False로 바꾸는 것도 상체 영역을
마스킹해 기존 니트를 지울 수 있으므로 확실한 해결책이 아닙니다.

다음 개선 실험은 합성 인물로 진행하는 것이 적절합니다.

- 같은 아우터의 **앞이 열린 사진**과 닫힌 사진을 비교하고, 하의+상의 단계와 아우터 단계 결과를
  따로 확인해 니트가 사라지는 정확한 단계를 분리합니다.
- 안쪽 니트 영역을 보존하는 편집 마스크 또는 여러 의류를 함께 조건으로 받는 합성 방식을
  검토합니다. 임의의 직사각형 붙여넣기는 자세·그림자·경계가 어색해질 수 있습니다.
- 앞이 닫힌 사진만으로 열린 착용을 만들면 보이지 않는 재킷 안쪽을 모델이 추정해야 하므로,
  원본 의류 재현과 착용 스타일 변경을 구분해 품질을 평가합니다.

이번 아우터 요청은 원인 판단을 우선하므로 합성 순서와 기존 옷장 이미지를 유지했습니다.
첨부된 개인 사진은 프로젝트·로그·새 테스트 데이터에 복사하거나 GPU 테스트에 사용하지 않았습니다.
이 문서에는 얼굴 이미지나 식별 특징을 기록하지 않습니다.

## 적용 및 검증 결과 — 2026-11-11

- 실제 PostgreSQL 전체 회귀 **500개 통과·2개 제외**, 기존 deprecation 경고만 남았습니다.
  제외 항목은 별도 외부 checkout/실사 입력이 필요한 기존 선택 테스트입니다.
- 실제 GPU에 합성 인물로 1단계 보정 후 3명이 상의·하의를 동시 요청했습니다.
  처리 순서는 **A → C → B → A → C → B**, 완료 시각은 요청 시작 후
  A 33.266초, C 41.297초, B 49.594초였습니다.
- 약 3초 시점의 최초 유효 예측은 A 34초 남음(25~43초), C 43초 남음(32~54초),
  B 52초 남음(39~66초)이었습니다. 예측 완료 시각에서 실제 완료 시각을 뺀 오차는
  각각 +3.766초, +4.782초, +5.453초였으며 모두 초기 표시 범위 안에서 완료됐습니다.
  한 번의 합성 사진 실측이며 모든 사용자나 p95 정확도를 보장하지 않습니다.
- 로컬·멘토 양쪽 접수, 중복 429, 타 사용자 접근 404, 공개 Funnel HTTPS 결과 200,
  취소 후 예약 반환 및 고객 사진/결과의 비영구 보관을 함께 확인했습니다.
- 실제 브라우저에서 별도 임시 계정으로 합성 사진 업로드 → 생성 →
  **상의 입히는 중 2/2 · 코디 완성까지 약 7초~11초 (초기 예상)** 표시를 확인했습니다.
- GPU를 한 번 더 안전하게 재시작한 뒤에도 익명 시간 통계 파일 해시가 동일하며
  GPU/로컬/멘토가 정상 복구됨을 확인했습니다. 통계 로딩·설정 변경 시 무효화는 회귀 테스트로 검증했습니다.
- 동시 검증 계정 3개와 화면 검증 계정 1개만 삭제했습니다. 기존 계정 7개·의류 45개·
  저장 착샷 3개를 포함한 기존 업무 레코드 해시와 이미지 파일 117개·자격 파일 4개 해시가 유지됐습니다.
  검증 중 생긴 정상 추천 기록도 보존했습니다. `.env`는 읽거나 수정하지 않았습니다.
- Git 제외 경로 `.demo/tryon-eta/`에 테스트 보고서·숫자 측정 기록·합성 테스트 화면을 보관합니다.
  개인 첨부 사진은 이 검증 자료에 포함되지 않습니다.
