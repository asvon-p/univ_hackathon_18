# 아우터 투명 레이어와 관리자 화면

2026-11-13 적용. 기존 데이터와 이미지를 보존하는 migration `0021`을 사용합니다.

## 문제와 변경

이전에는 아우터와 이너의 색 차이로 열린 영역을 판단했습니다. 판단이 불확실하면 아우터 적용 전체를 생략했고, 단순히 제품의 중앙 영역을 몸에 확대하면 네모난 복원 경계와 모델이 만든 이너·목 칼라가 남았습니다.

현재 처리 순서는 하의 → 상의 → 아우터입니다. 아우터 직전의 상의 적용 이미지를 보존 기준으로 사용합니다.

1. 저장된 누끼를 사용하고, 없으면 로컬 rembg로 생성합니다. 원본은 덮어쓰지 않습니다.
2. 작은 알파 잡티를 제거하고 가장자리를 부드럽게 처리합니다. 경계의 RGB는 가까운 불투명 원단에서 확장해 흰 테두리를 줄입니다.
3. 아우터의 안쪽 영역을 사용자가 직접 지정하면 투명 PNG에서 제거합니다. 좌표는 의류 DB에, 처리 지시는 PNG 메타데이터에 넣습니다.
4. GPU가 아우터를 적용한 뒤 지정 영역을 몸통에 대응시킵니다. 이를 기준으로 생성 이미지의 연결된 안쪽 경계를 찾아 기존 상의·목선·필요한 바지 부분을 복원합니다. 얼굴·머리·손 영역은 보호합니다.
5. 미지정 또는 경계 구분이 어려운 경우에는 근사 영역을 사용하며, 자동 추정 결과는 안내합니다. 신체 정렬 자체가 안 될 때는 여전히 안전하게 생략할 수 있습니다.

제품의 투명 PNG는 실제 3D 의상이나 물리 시뮬레이션이 아닙니다. 큰 자세 변화, 닫힌 아우터, 비슷한 원단 색, 비대칭·복잡한 개방부에서는 경계가 부정확할 수 있습니다. 기존 결과를 다시 쓰지 않도록 새 렌더 버전 `opening-layer-v2`를 사용하고, 영역 변경 시 해당 의류의 수정 시각으로 재사용을 무효화합니다. 과거 결과는 이력에 남습니다.

## 사용자 조작

옷장 → 의류 상세 → **누끼 정제·아우터 안쪽 설정**.

- 앞을 연 아우터를 정면에서 촬영합니다. 소매와 라펠은 남기고 안감·빈 배경에 해당하는 중앙 영역을 순서대로 3~24점으로 지정합니다.
- 교차하거나 오목한 영역은 거부합니다. 마지막 점 취소와 초기화를 지원합니다.
- 저장 후 바둑판 배경으로 투명 영역을 확인합니다. 다음 착샷부터 적용됩니다.
- 원본 이미지, 의류 ID, 기존 의류 속성은 변경하지 않습니다.

관련 API: 본인 JWT가 필요한 `GET/PUT /api/v1/garments/{id}/layer-config`, `GET /api/v1/garments/{id}/layer-image`. 다른 사용자 의류는 404입니다.

## 관리자

기존 `test@example.com`에만 관리자 역할을 부여했습니다. 비밀번호는 바꾸지 않았습니다. 다음 화면에 기존 로그인으로 접속합니다.

- 로컬: `http://127.0.0.1:3000/admin`
- 멘토: `https://sgy-host.taile39b25.ts.net:8443/admin`

로그인 후 관리자 메뉴가 나타납니다. 메뉴 숨김과 별개로 모든 관리자 API 및 이미지 요청은 DB의 `is_admin`을 확인하며, 비회원 401·일반 사용자 403입니다. 가입/프로필 요청으로 권한을 바꿀 수 없습니다. 소스 폴더 공개 차단은 유지됩니다.

권한 부여/회수는 웹 API 없이 해당 PC의 명시적인 CLI로만 가능합니다.

```powershell
$env:FITJANG_SKIP_DOTENV = '1'
python -m scripts.admin_account --email test@example.com --grant
# 필요한 경우: python -m scripts.admin_account --email test@example.com --revoke
```

요청에 따라 공유 운영 DB에서 `qa-test@example.com`, `mentor-demo@example.com`, `customer-validation@example.com`을 삭제했습니다. 프로필·옷장·추천·착샷과 해당 사용자 파일을 기존 탈퇴 서비스로 정리하고 피드백은 익명화합니다. 두 서버가 같은 DB이므로 양쪽에 적용됩니다. 별도의 과거 백업을 복원하면 삭제 상태도 고려해야 합니다.

## 사용량과 비용

`api_usage`에는 호출 시도, 모델, 입력·캐시 입력·출력 토큰, 상태, USD 추정 비용만 기록합니다. 프롬프트, 응답 본문, 키, 사진은 기록하지 않습니다. 장부 저장이 실패하면 유료 호출 전에 local 추천으로 대체합니다. 응답 유실·지원하지 않는 모델/과금 조건은 비용 미확인으로 남습니다. 추천 재요청의 기존 Idempotency-Key는 장부 중복도 방지합니다.

적용 이후 이 서비스에서 발생한 호출만 집계합니다. 과거/다른 프로젝트 사용량은 복원하지 않습니다. 사용 금액은 **추정치**이며 세금·크레딧·조직 할인 등을 반영한 청구액이 아닙니다. 조직 Billing API에 필요한 별도 관리자 자격은 연결하지 않았습니다. 실제 청구액은 화면의 OpenAI 사용량 링크로 확인합니다.

일반 처리의 GPT-6-Luna 단가는 2026-11-13 확인한 공식 모델 문서를 기준으로 입력/캐시 입력/출력 100만 토큰당 USD 0.10/0.01/0.50입니다. 특수 서비스 티어는 미확인 처리합니다. 단가 변경 시 `api_usage.estimate`를 갱신해야 합니다.

근거: https://developers.openai.com/api/docs/models/gpt-6-luna

## 처리 이미지 보관

관리자는 사용자 UUID로 범위를 좁혀 원본·기존 누끼·정제 레이어와 하의/상의/아우터/최종 착샷을 확인할 수 있습니다. 사진은 비공개 인증 경로로만 제공하고 캐시하지 않습니다. 기존 누끼가 없으면 누끼 항목은 원본 대체이며, 정제 항목에서 실제 새 누끼를 생성합니다.

새 착샷의 중간 이미지는 최종 이미지와 같은 사용자/결과 폴더에 저장합니다. 파일 저장·DB 커밋 실패 시 기존 정리 작업으로 전체를 회수합니다. 프로필의 전신 사진·착샷 완전 삭제, 결과 개별 삭제, 회원 탈퇴 시 단계 이미지도 함께 삭제됩니다. `session` 보관 정책 계정은 DB/파일에 중간 이미지를 저장하지 않습니다. 과거에 저장하지 않은 단계와 삭제된 사진은 복원하지 않습니다.

## 검증

- 중복 실행을 제외한 최종 테스트 결과 **518 passed, 0 failed, 0 skipped**. 최초 회귀에서 변경된 이미지 경로를 반영하지 못한 프론트 대역 테스트 4개는 수정 후 해당 파일 전체를 재검증했습니다. 집계는 각 테스트의 마지막 실행 결과 기준입니다.
- PostgreSQL 임시 스키마의 관리자 접근, 역할 회수, 가입 권한 상승 차단, 누끼 원본 보존, 타 사용자 접근 차단, 단계 파일/DB 실패 정리 및 기존 인증·추천 회귀.
- 실제 HTTP + PostgreSQL + OpenAI 응답 대역으로 동시·중복 추천의 장부 중복 방지 검증.
- 로컬 GPU에 기존 생성 에셋인 합성 인물과 열린 봄버, 아이보리 니트, 청바지를 사용. 사용자 개인 사진은 테스트에 사용하지 않음.
- 실제 GPT 호출 1회: 입력 701·캐시 0·출력 103토큰, USD 0.00012160 추정. 동일 요청 재전송 후에도 장부 1개.
- `.demo/admin-layers/`에 테스트 로그, 합성 비교 이미지, 화면 검증, 보존 대조 기록을 Git 제외 산출물로 보관.
- 실제 공인 DNS 경로의 HTTPS에서 관리자/이미지 200, 권한 회수 후 같은 JWT로 403, 소스 경로 404, 로컬과 공개 결과 바이트 일치를 확인했습니다. TLS 인증서 검증은 유지했습니다.
- 삭제 대상 외 기존 계정 6·프로필 6·의류/속성 각 32·추천 68·코디 93·기존 착샷 1과 원본 파일 90개의 크기·수정시각을 보존했습니다. 관리자 부여에 따른 해당 사용자 행의 `is_admin`/`updated_at` 변경은 의도된 변경입니다. 임시 합성 검증 계정은 삭제했고 사용량 장부만 사용자 연결이 제거된 상태로 남습니다.

`.env` 직접/간접 접근은 금지 상태를 유지하고, 테스트와 실행기 모두 `FITJANG_SKIP_DOTENV=1` 및 접근 차단 audit hook을 사용합니다.
