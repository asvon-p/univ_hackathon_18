# 열린 셔츠를 아우터로 입히는 착샷 개선

2026-11-13. 착용 역할 `outerwear`, 옷 형태 `shirt`인 의류를 대상으로 생성한 열린 셔츠 사진과 기존 합성 인물로 비교했다. 사용자 개인 사진은 사용하지 않았다.

## 재현한 원인

1. 누끼 모델이 열린 셔츠 중앙의 흰 배경을 일부 불투명·반투명하게 남겼다. 일부 RGB도 알파와 함께 어두워져 중앙 색상이 높이별로 달라졌다.
2. 자동 탐지는 중앙이 충분히 불투명한 픽셀만 색상 표본으로 사용해, 이렇게 남은 긴 빈 영역을 연결하지 못했다.
3. 기존 누끼 경계 정제는 원단에서 멀리 떨어진 반투명 픽셀까지 가장 가까운 원단 색으로 채웠다. 결과적으로 열린 셔츠 중앙에 원단이 생긴 것처럼 GPU에 전달됐다.
4. 아우터 출력 후 상의 복원은 목 주변에 몸통 전체 폭에 비례한 직사각형을 적용했다. 이 때문에 셔츠 칼라가 지워졌다. 복원 후보에 배경까지 포함되어 어깨 밖에 이전 니트의 밝은 테두리도 남았다.

## 변경 사항

- 같은 크기이며 불투명 원단 색상이 일치하는 누끼에만 원본 RGB를 다시 결합한다. 알파 마스크는 유지하고, 원본과 누끼 파일 자체는 수정하지 않는다. 크기·원단 색상이 맞지 않는 외부 누끼는 임의로 맞추지 않는다.
- 중앙의 부분 투명 영역도 색상 탐지에 포함한다. 양쪽 원단 경계, 연속성, 길이, 폭과 볼록 영역 검사는 유지한다. 탐지 버전은 `product-opening-v2`다.
- 원단 색으로 가장자리를 보정하는 범위는 경계에서 2~5픽셀 이내로 제한한다. 넓은 빈 영역으로 원단 색을 확장하지 않는다.
- 합성된 셔츠의 실제 열린 윤곽에 맞춰 이전 상의 픽셀을 복원한다. 생성 결과의 배경을 복원 후보에서 제외하고, 어두운 칼라·단추선을 보존한다.
- 목 주변 복원 폭을 열린 영역에 맞추고, 경계 블렌딩은 열린 영역 안쪽에서만 수행한다. 모델이 가상의 안쪽 티셔츠를 바지에 넣어 입혀도 원래 선택한 상의 밑단을 보존한다.
- 열린 폭이 지나치게 좁아지면 관찰된 앞여밈을 제품 사진의 열린 폭에 맞춰 조금 벌린다. 단추·앞단 원단을 함께 이동시키고 칼라·바깥 실루엣은 고정한다. 이동은 한쪽당 몸통 기준 폭의 6% 이내로 제한하며, 충분히 연속적인 열린 윤곽과 명시적인 제품 영역이 있어야 적용한다.
- 한 출력의 의류 분할 결과는 재사용한다. 개인 식별, 얼굴 인식, 학습 데이터 저장은 추가하지 않는다.
- 렌더 버전은 `open-shirt-v4.1`이다. 기존 착샷은 조회 가능하게 보존하고, 새 생성에는 이전 처리 버전의 결과를 재사용하지 않는다. API는 이전 렌더 버전도 계속 읽고 저장할 수 있다.

## 검증 범위

단위 회귀는 반투명한 긴 구멍, 닫힌 옷·목구멍·무늬의 오인식 방지, 원본 정렬 확인, 경계 색상 확산, 셔츠 칼라·단추·상의 질감·어깨 배경, 기존 긴 코트의 목·바지 복원을 다룬다. PostgreSQL에서는 사용자별 접근 차단, 역할/형태 유지, 원본·누끼·수정 시각 보존, 새 렌더 버전 저장과 기존 결과 조회를 검증한다.

GPU 런타임의 회귀 테스트 17개가 통과했다. PostgreSQL을 활성화한 백엔드 검증은 초기 145개, 마지막 버전 변경 뒤 영향 범위 41개가 통과했다(중복 실행 포함). 실패·건너뜀은 없었다. 좁은 여밈을 벌릴 때 단추 이동, 칼라·외곽 유지, 관찰된 열린 영역이 없을 때 변형하지 않는 경우도 포함한다.

동일한 GPU 원시 출력에 이전/수정 후 복원을 각각 적용한 합성 비교에서는 검사한 칼라·어깨 픽셀이 생성한 셔츠/배경과 정확히 일치했고, 안쪽 니트 질감·밑단과 보호 영역은 이전 상의 단계와 일치했다. 이는 해당 비교 이미지의 지정 위치 검사이며 모든 의류에 대한 품질 점수는 아니다.

검증 기록은 Git 제외 경로 `.demo/open-shirt/`에 둔다. `baseline.jpg`는 개선 전 실제 GPU 결과, `raw-improved-outer.png`는 개선된 누끼를 입력한 원시 GPU 결과, `clean-layer-old-compositor.png`와 `improved-compositor.png`는 같은 출력에 적용한 후처리 비교다. `comparison-metrics.json`은 픽셀 검증 결과다.

## 실제 서버와 화면 확인

- 로컬 UI `127.0.0.1:3000`, 멘토 UI `127.0.0.1:3001`, API 8002/8003과 GPU 8010에 반영했다. 공개 주소는 `https://sgy-host.taile39b25.ts.net:8443`이다.
- 공개 추천 결과 화면에서 합성 인물의 하의 → 상의 → 아우터를 생성했다. 자동 열린 영역 탐지와 `outerwear`/`shirt` 역할·형태를 유지했고, 최종 결과는 `open-shirt-v4.1`, `layering_status=applied`로 PostgreSQL에 저장됐다.
- 공개 결과 모달과 로컬 홈 모달이 같은 저장 결과를 표시하고 이미지가 실제로 로딩된 것을 확인했다. 화면 기록은 `public-result.png`, `local-result.png`, 최종 이미지와 메타데이터는 `improved.jpg`, `improved.json`이다.
- 개선 전 결과도 같은 계정으로 조회할 수 있었으며 응답 이미지 바이트가 이전 산출물과 일치했다. 비로그인 이미지 요청은 401로 차단됐다. 다른 사용자 접근 차단은 실제 PostgreSQL API 테스트로 검증했다.
- 이번 임시 합성 검증 계정은 종료 후 삭제했다. 기존 계정 6개, 의류 39벌, 추천 68건, 기존 착샷 1건과 파일 112개에 변경이 없었다. 기존 DB 행 해시 및 파일 크기·수정 시각 비교는 `preservation.json`에 기록했다. 테스트 추천의 API 사용량 기록 1건은 과금 감사 이력으로 남는다.
- 새로 생성하는 착샷에 개선이 적용된다. 이전 결과를 덮어쓰거나 기존 의류 ID·속성·개인 사진을 변경하지 않는다.

## 한계

2D 생성 및 영상 합성이므로 실제 원단의 3D 움직임을 계산하지 않는다. 이번 열린 셔츠도 생성 모델이 원본보다 짧게 표현할 수 있다. 닫힌 셔츠나 가려진 여밈, 같은 색의 안감, 교차한 팔 등에서는 열린 영역 수동 수정이나 재촬영이 필요하다. 열린 셔츠 한 사례의 개선을 모든 자세·의류의 자연스러움 보장으로 해석하지 않는다.

## 생성 검증 이미지

- 도구: 내장 imagegen, 신규 생성. 개인 사진 또는 사용자 의류 사진을 참조하지 않았다.
- 저장: `.demo/open-shirt/open-blue-shirt.png` (프로젝트 내부 검증 자산).
- 인물: 기존 생성 자산 `.demo/tryon-assets/person-01.png`.
- 프롬프트: `.demo/open-shirt/imagegen-prompt.txt`.
- 생성 이미지는 실제 제품·인물의 촬영 사진이 아니다.

`.env` 직접·간접 접근을 금지하고 `FITJANG_SKIP_DOTENV=1`과 파일 접근 감사 훅을 사용한다. 기존 계정과 데이터를 초기화하지 않는다.
