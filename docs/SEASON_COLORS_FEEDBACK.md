# 기온 대체·다중 색상·상세 피드백 (2026-11-15)

## 기온을 불러오지 못했을 때

- 추천 화면에서 **계절·월 평균으로 추천받기**를 선택할 수 있다. 위치 확인은 최대 6.5초, 개별 날씨 요청은 최대 7초 후 중단한다. 위치 기온 조회가 실패하면 서울 조회를 시도하고, 그것도 실패하면 계절 모드로 전환하여 사용자가 확인할 수 있게 표시한다.
- 사용자가 계절이나 직접 기온을 변경하면 늦게 도착한 날씨 응답은 무시한다. 계절·월 조건은 일정·참고 스타일 관리 화면을 다녀오거나 저장 결과에서 조건을 수정할 때도 유지된다.
- `POST /api/v1/recommendations`에 `season`(spring/summer/autumn/winter), `month`(1–12)를 보낸다. 계절을 명시하면 수동 기온·위치보다 우선하며 서버가 평균값을 다시 계산한다. 월 생략 시 현재 한국 월이 같은 계절이면 해당 월, 다른 계절이면 4/7/10/1월을 사용한다. 계절과 월이 맞지 않으면 422.
- 봄 3–5월, 여름 6–8월, 가을 9–11월, 겨울 12–2월. 1월부터 평균 기온은 **−0.6, 1.5, 6.4, 12.3, 17.5, 21.6, 24.8, 25.3, 20.7, 14.6, 7.9, 1.5°C**.
- 출처: [기상청 신기후평년값(1991–2020), 전국 월별 평균기온](https://www.kma.go.kr/kma/flexer/html/press/2021/03/25/ATC202103250932093_863521e7-fd31-4f26-bfce-04a9e14ffb33.hwp.files/Sections1.html). 지역·당일 날씨를 대변하지 않는다. 응답과 DB에는 `weather.source=seasonal`, `is_fallback=true` 및 출처를 기록한다. GPT에도 월평균 대체값임을 전달한다.

## 메인·서브 색상

- 기존 `color`를 메인 색상으로 유지하고 `secondary_colors` 배열(최대 3개)을 추가했다. 기존 행은 빈 배열로만 확장하며 기존 분류·사진은 다시 분석하지 않는다.
- 새 의류 분석은 누끼 전경에서 비중이 가장 큰 색상을 메인, 일정 비중(12%) 이상인 색상을 서브 후보로 제안한다. 사진의 그림자·조명에 따른 오차는 확인 화면에서 수정할 수 있다. 참고 사진의 기존 `multi` 계약은 유지한다.
- 중복·메인과 같은 색·multi/unknown 서브 색상은 거절한다. 메인만 변경하여 기존 서브와 겹치면 해당 서브를 제거한다. 색상 중 하나라도 수동 수정하면 재분석은 메인과 서브를 모두 보존한다.
- 일반·일정·참고 스타일 추천과 GPT 후보 정보에 함께 전달한다. 색상 조화 점수는 기존 메인 점수 70%, 전체 팔레트 평가 30%로 반영한다. 서브가 없으면 기존 점수와 같다. 참고 색상이 서브에만 있으면 메인 일치보다 낮게 평가한다.

## 상세 피드백

- 별로예요 클릭 → 이유 선택·자유 의견 모달 → 저장 성공 후 검은 배경으로 선택 표시. 취소는 기존 선택을 바꾸지 않는다. 결과 조회 시 가장 최근 선택과 작성 내용을 복원한다. 좋아요도 같은 검은 선택 표시를 사용한다.
- API는 기존 `reason`(최대 1,000자)과 `reason_codes`(colors/style/too_warm/too_cold/combination)를 저장한다. 본인 소유 추천·코디에만 작성·조회할 수 있다.
- 다음 새 추천에서 최근 20개 코디의 최종 의견만 반영한다. 동일 조합 중복 의견은 점수를 누적하지 않는다. 별로예요의 동일 조합은 15점 감점, 색상·스타일 유사 조합은 최대 10점, 보온도 의견은 최대 8점 감점한다. 총 보정은 −15~+6으로 제한한다. 좋아요 동일 조합은 6점 가점한다.
- 직접 작성한 문장의 의미 판단은 GPT에 전달하며 명령으로 취급하지 않는다. local 대체 추천에서는 명시적으로 고른 이유와 동일 조합 회피를 반영한다. 모델 재학습은 하지 않는다. 현재 옷 속성을 비교하므로 의류 수정·삭제에 따라 피드백 반영 대상도 달라질 수 있다.
- 기존 결과를 새로고침하면 결과 조회만 하며 GPT를 재호출하지 않는다. 반영 여부는 **다음 새 추천**으로 확인한다. 필수 의류·일정 복장 조건과 소유권 제한은 순위 보정보다 우선한다. 모든 옷을 필수로 지정했거나 대체 조합이 없으면 같은 코디가 유지될 수 있다.

## 데이터와 실행

- Alembic `0025`는 `garment_attributes.secondary_colors`, `feedback_events.reason_codes`만 추가한다. 기존 데이터 삭제·의류 일괄 재분석은 하지 않는다.
- `.env`는 직접·간접 접근하지 않는다. 기존 dotenv 차단 실행기를 사용한다. PostgreSQL 테스트는 별도 임시 스키마에서 실행하고 종료 시 정리한다.

## 검증 기록

- 실제 PostgreSQL 임시 스키마: 12개월·잘못된 계절/월 입력, 서브 색상 제한·재분석 보존·타인 차단, local/GPT 응답 모사/API 실패 대체 추천의 순위 변화, 필수 의류·일정·참고 사진 유지, 최신 의견 우선, 마이그레이션 기존 행 보존 통과.
- 기존 날씨·피드백·옷장·재분석·착용 역할·GPT·마이그레이션 회귀 테스트, 일반·일정 추천 단위 테스트, 실제 HTTP 프론트 E2E 통과. Windows 정책으로 차단된 psycopg 대신 기존 pg8000 대체 엔진을 E2E DB 검증에도 적용했으며 보안 정책은 변경하지 않았다.
- 390×844 브라우저: 날씨 실패를 주입한 별도 로컬 화면에서 자동 계절 전환 → 추천 생성, 12월 1.5°C 및 일정 화면 왕복 후 조건 유지 확인.
- 공개 HTTPS: 피드백 모달 작성·취소·저장·새로고침, 검은색 선택 표시, 서브 색상 3개 저장·4번째/메인 중복 선택 차단 확인. 실제 GPT 판단으로 ‘슬랙스보다 청바지’ 의견 제출 후 청바지 조합이 3위에서 1위로 변경되었다.
- 검증용 계정은 삭제했고 토큰 차단도 확인했다. 기존 계정 34개, 의류 305개, 이미지 파일 694개와 기존 DB 행 해시가 모두 유지되었다. 서비스 정책에 따라 검증 계정의 익명 피드백 1건 및 실제 API 사용 2건의 운영 통계는 남는다.
- 로컬 3000/8002, 멘토 3001/8003 및 기존 GPU 서버 정상 응답 확인. iPhone 실기기 자체는 접근할 수 없어 검증하지 않았다.
