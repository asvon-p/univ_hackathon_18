# 의류별 보온 조건과 추위·더위 피드백

## 수정 이유

기존 일반 추천은 추운 날 모든 의류에 과도하게 높은 보온도를 요구했고, 후보가 없으면 대체 추천이 기온 조건을 무시했다. 일정 추천에서는 상의·하의·아우터의 보온도를 가중 합산해 두꺼운 아우터가 얇은 상의를 보완할 수 있었다. 자유 입력 의견은 local 추천에서 보온 조건으로 해석되지 않았으며, 저장된 결과 새로고침은 새 추천을 생성하지 않는다.

## 공통 보온 정책

`shared/thermal_policy.py`를 일반·일정·참고 스타일·GPT 후보 생성·대체 추천·최종 결과 검증에서 함께 사용한다. 보온도는 1(매우 얇음)~5(매우 두꺼움)의 서비스용 분류이며, 실제 체감온도나 의복의 물리적 보온력을 측정한 값은 아니다.

| 기온 | 상의 최소 | 하의 최소 | 아우터 최소 | 아우터 필요 여부 |
|---|---|---|---|---|
| 0°C 미만 (영하) | 4 두꺼움 | 4 두꺼움 | 5 매우 두꺼움 | 필수 |
| 0°C 이상~5°C 이하 | 3 보통 | 3 보통 | 4 두꺼움 | 필수 |
| 5°C 초과~15°C 이하 | 3 보통 | 3 보통 | 3 보통 | 필수 |
| 15°C 초과~22°C 이하 | 2 얇음 | 2 얇음 | 2 얇음 | 선택 |
| 22°C 초과 | 1 매우 얇음 | 1 매우 얇음 | 1 매우 얇음 | 선택 |

- 각 역할이 따로 최소값을 충족해야 한다. 아우터가 5여도 상의가 1이면 −3°C 추천에서 제외한다.
- 2026-11-21 사용자 요청으로 영하 전체를 가장 추운 구간으로 변경했다. 0°C는 두 번째, 5°C는 두 번째, 15°C는 세 번째, 22°C는 네 번째 구간에 속한다. 정책 버전은 `slot-warmth-v3-season-forecast`, 일정 결과 버전은 `day-plan-v4-season-forecast`이다.
- 과도한 두께 제한은 고려하는 기온 중 최저를 기준으로 적용한다(15°C 초과~22°C 이하는 최대 4, 22°C 초과는 최대 2). 하루 종일 더운 경우 두꺼운 의류는 제외하지만, 낮은 덥고 밤이 추우면 추위에 필요한 두께를 허용하고 더운 구간은 별도 점수·착용 안내로 평가한다.
- 기온을 검사하는 구간에서는 보온도 미확정 의류를 통과시키지 않는다. 기존 의류 속성을 임의로 덮어쓰지 않으므로 필요한 경우 사용자가 보온도를 확인해야 한다.
- 명시적으로 반팔·반바지로 분류된 의류는 아우터가 필수인 구간(15°C 이하)에서 제외한다. `t-shirt` 같은 넓은 형태 분류만으로 소매 길이를 단정하지 않으며 이때는 보온도를 기준으로 판단한다.
- 실내·실외·혼합·미확정 일정 모두 남은 시간 예보(없으면 현재/수동 기온)를 공통 기준으로 사용한다. 일정에 직접 입력한 최저·최고가 더 극단적이면 이를 함께 고려하며, 실내 일정이라는 이유로 바깥 추위를 지우지 않는다. 실제 실내 기온은 추정하지 않는다.
- 일정의 더운 구간은 아우터를 벗어 소지할 수 있으므로, 최소 조건을 강제하고 과도한 두께는 별도 점수와 착용 안내에 반영한다. 옷별 보온도의 합산은 사용하지 않는다.
- 필수 선택 의류와 기온 조건이 충돌하면 다른 옷으로 몰래 교체하지 않는다. 가능한 조합이 없으면 `NO_FEASIBLE_OUTFIT`(422)과 필요한 의류별 보온도를 안내한다. GPT 실패나 후보 부족도 이 제한을 완화하지 않는다.

## 계절과 실내 기준

추천 폼의 `clothing_season`은 실내 복장 계절이다. 기존 `season/month`는 날씨 조회 실패 시 월평균 대체 기온 입력으로, 둘을 분리해 실제 예보를 쓰면서도 계절을 선택할 수 있다. 화면 기본값은 한국 시간 현재 월에 해당하는 계절이다.

- 겨울의 **실내** 일정: 상의 최소만 실외보다 1단계 낮춘다(최소 1). 영하라면 상의 3·하의 4·아우터 5. 아우터·하의 기준은 그대로다.
- 여름의 **실내** 일정: 상하의는 같은 기온의 실외 기준을 유지한다. 외부 추위 때문에 두꺼운 아우터가 필수인 경우를 제외하면 냉방용 얇은 아우터(1~2)를 우선한다. 없으면 포함하지 못했다는 안내를 제공한다.
- 봄·가을, 실외·혼합·미확정 일정은 실외 기준 그대로다. 여러 일정이 섞이면 각 일정의 조건을 모두 만족해야 한다. 따라서 겨울에도 실외 일정이 하나 있으면 상의 완화가 전체 복장의 기준을 낮추지는 않는다.
- 일정 없는 추천은 실외 기준이다. 계절만 선택했다고 실내로 간주하지 않는다.

## 지금부터 오늘 자정 전까지 예보

Open-Meteo `temperature_2m` 시간별 예보를 조회한다. 범위는 **추천 시각부터 다음 날 00:00 미만(Asia/Seoul)**이다. 이미 지난 새벽의 최저기온과 다음 날의 기온을 최솟값·최댓값 표본에 넣지 않는다. 현재 시각의 값은 인접 시간 사이를 보간하며, 다음 날 00시 값은 23시 이후 보간용으로만 사용한다. 따라서 값은 남은 시간의 시간별 표본 기반 예상 범위이며 분 단위 극값 관측이 아니다.

- 최저로 의류별 최소 보온도를 정하고 최고까지 평가해 일교차에 따른 과도한 두께를 순위에 반영한다. 예: 최저 3°C·최고 25°C이면 실외 기준 상하의 3 이상, 아우터 4 이상. ‘구간별로 벗고 소지 가능’에서는 추운 때 착용하고 더운 때 벗도록 안내한다.
- ‘계속 입기’ 설정은 자동 변경하지 않는다. 예보는 특정 일정의 실제 실내 온도를 측정한 것이 아니며, 각 일정은 공통 남은 시간 범위를 사용한다. 특정 일정 시간으로 예보를 축소하거나 귀가 이후 시간을 자동 제외하지 않는다.
- `/api/v1/weather`는 좌표 없는 예보와 사용자별 서명 확인값을 반환한다. 추천은 이를 검증·재계산한다. 다른 사용자, 변조, 만료된 예보는 거절한다. 유효기간은 조회 후 30분 또는 자정 중 빠른 시각이며 화면에서 재조회/수동 입력을 안내한다. 예보의 확인값은 로그인 인증으로 사용할 수 없다.
- 날짜가 다른 일정에 오늘 예보를 붙이지 않는다. 오늘 일정을 고르거나 수동 기온을 사용하도록 422로 안내한다.
- 예보 자체가 없으면 현재 기온만, 전체 날씨 조회가 실패하면 기존 수동·계절/월 대체 입력을 사용한다. 실패한 예보를 실제 예보처럼 표시하지 않는다.
- 기존 JSON 문맥에 계절·예보 스냅샷만 보관한다. 좌표와 예보 확인값은 추천 기록에 저장하지 않는다. 저장된 추천 GET은 당시 결과를 유지하고, 재추천 POST는 유효한 예보에서 현재 시각 이후만 다시 계산한다. 계절·예보는 일정 관리 화면 이동에도 유지된다.

## 피드백 반영과 다시 추천

- 명시적으로 선택한 `too_cold`/`too_warm`을 우선한다. 자유 입력 중 ‘추워요’, ‘영하인데 반팔이에요’, ‘너무 두꺼워서 더워요’처럼 명확한 표현도 같은 코드로 처리한다. 부정·상반 표현은 추정하지 않는다. 모든 자연어 의견을 이해하는 기능은 아니므로 이유 선택을 함께 안내한다.
- 기존 텍스트 의견도 조회 시 해석한다. 저장된 피드백·추천 기록은 수정하지 않는다.
- 같은 사용자·같은 옷장 범위에서 최근 의견을 사용한다. 내 옷장과 테스트 옷장은 분리된다. 원래 추천의 기준 기온과 이번 기온 차이가 5°C 이내인 최근 유효한 추위·더위 의견에만 필수 보온 개선 조건을 적용한다.
- 춥다는 의견 뒤에는 역할별 보온도가 낮아지지 않으면서 적어도 한 역할이 더 따뜻한 조합을 찾는다. 덥다는 의견은 반대로 적용한다. 개선 가능한 옷이 없으면 같은 조합을 반복하지 않고 조건 부족을 안내한다. 같은 조합에 더 최근에 남긴 좋아요는 이전 부정 의견을 대체한다.
- 결과 화면의 **피드백 반영해 다시 추천**은 새 요청 키로 POST하며 기온·스타일·필수 의류·일정·참고 스타일·옷장 범위를 유지한다. 피드백 저장 중에는 버튼을 잠근다. GET 새로고침과 동일 요청 재전송은 기존 결과만 조회한다.
- 보온 조건은 서버가 결정한다. GPT는 통과한 후보의 순서와 이유를 판단하며, 조건을 무시하거나 존재하지 않는 옷을 추가할 수 없다. 이번 수정은 모델 재학습이 아니며 텍스트 보온 의견 해석에 추가 GPT 호출을 쓰지 않는다.

## 저장과 검증

DB 스키마 변경이나 데이터 마이그레이션은 없다. 기존 계정·옷·이미지·추천·피드백을 보존한다. 새 추천부터 정책이 적용되며 기존 결과 URL의 코디는 변경하지 않는다.

- `backend/tests/test_thermal_policy.py`: 기온 경계, 역할별 최소값, 모든 추천 경로, 필수 의류 충돌, 텍스트 해석, GPT 실패 대체.
- `backend/tests/api/test_thermal_feedback.py`: 실제 PostgreSQL에서 기존 텍스트 의견 반영, 사용자·옷장 분리, 부족 조건의 422, 과거 기록 보존.
- `backend/tests/e2e/test_thermal_feedback.py`: 로컬·멘토 프론트 구성에서 의견 저장 → 조건 유지 재추천 → 더 따뜻한 상의 선택 → 새로고침·중복 요청의 불변성.
- `backend/tests/test_remaining_forecast.py`: 과거 시간 제외, 자정 경계, 만료, 계절별 실내 조건, 일교차의 아우터 조절, 더운 날 두꺼운 의류 제외.
- `backend/tests/api/test_remaining_forecast.py`: 실제 PostgreSQL 저장·조회·중복 처리, 예보 소유자와 유효기간, 수동 기온과 독립된 계절 선택.
- `backend/tests/e2e/test_remaining_forecast.py`: 로컬·멘토 구성의 실제 HTTP 추천·일정 이동·재추천·새로고침.

테스트는 독립 스키마와 합성 이미지로 수행하며 `.env`를 읽지 않는다.
