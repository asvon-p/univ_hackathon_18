# 아우터 안쪽 자동 투명화

2026-11-13 구현. 의류 상세의 **누끼 정제·아우터 안쪽 설정**에서 결과를 확인할 수 있습니다. 기본값은 자동이며, 인식이 맞으면 별도 저장이나 영역 지정 없이 착샷에 적용됩니다.

## 사용 흐름

1. 아우터의 앞을 열고 정면에서 촬영하거나 사진을 등록합니다.
2. 기존 누끼에서 중앙의 투명한 틈과 양쪽 원단과 구별되는 안감 영역을 찾습니다.
3. 길이·폭·연속성과 양쪽 원단 존재 여부를 검사해 확실한 영역만 투명 처리합니다. 작은 잡티와 경계 정제도 함께 적용합니다.
4. 잘못 인식한 경우에만 **잘못 인식했나요? 안쪽 영역 수정**을 펼칩니다. 자동으로 표시된 점을 끌거나 초기화 후 3~24점을 지정할 수 있습니다.
5. **수정한 영역 저장**, **자동 인식으로 되돌리기**, **안쪽 제거 안 함** 중 선택합니다. 직접 저장한 영역은 자동 인식이 덮어쓰지 않습니다.

영역이 불확실하면 원단을 임의로 잘라내지 않고 수정 안내를 표시합니다. 닫힌 옷을 열린 옷으로 복원하는 기능은 아닙니다. 닫힌 지퍼, 가려진 안쪽, 원단과 안감의 색상이 비슷한 사진, 비스듬한 사진은 수동 수정이나 재촬영이 필요할 수 있습니다.

## 처리와 데이터 보존

- `shared/outerwear_opening.py`: 의류 RGBA 이미지의 투명도·색상·형태를 이용하는 로컬 알고리즘입니다. 사람 사진이나 GPT API를 사용하지 않습니다. `confidence`는 내부 적합도 값이며 통계적으로 검증된 정확도 확률이 아닙니다.
- `GET /api/v1/garments/{id}/layer-config`: 적용할 좌표와 모드·인식 상태를 반환합니다. 자동 좌표는 계산값으로, GET 요청이 기존 DB 좌표나 수정 시각을 변경하지 않습니다.
- `PUT .../layer-config`: `mode=auto|manual|off`를 저장합니다. 수동 모드만 `points`를 받습니다. 자동·미사용 전환 시 이전 수동 좌표는 보존합니다.
- `GET .../layer-image`: 원본과 기존 누끼를 수정하지 않고 착샷용 PNG를 생성합니다. 동일하게 계산한 좌표와 모드를 PNG 메타데이터에 포함합니다.
- migration `0022`: `garments.opening_mode`를 추가합니다. 기존 수동 좌표가 있는 행은 `manual`, 나머지는 `auto`입니다. 의류 ID·속성·기존 파일은 유지합니다.
- 모든 의류 경로는 기존 사용자 소유권 검사를 거치며, 타 사용자 요청은 404입니다. 이미지 및 설정 응답은 비공개·캐시 금지입니다.

## 착샷 적용

하의와 상의를 먼저 입힌 결과를 보존하고, 아우터 생성 후 자동/수동으로 지정된 열린 영역에 기존 상의 픽셀을 복원합니다. 긴 코트는 복원 범위를 코트 길이에 맞추어 바지 앞부분까지 이어 줍니다. 목·얼굴·손 보호와 경계 블렌딩을 유지합니다.

렌더 버전은 `auto-opening-v3.2`입니다. 과거 결과는 삭제하지 않으며, 새 착샷 요청에는 새 처리 버전을 사용합니다. 사용자가 안쪽 제거를 끄면 이 복원 단계를 생략합니다.

이는 2D 이미지 생성과 영역 대응을 결합한 방식입니다. 실제 3D 원단 시뮬레이션이 아니므로 모든 자세와 의류에서 라펠·주름·경계 품질을 보장하지 않습니다.

## 검증 및 운영

- 실제 PostgreSQL 임시 스키마에서 신규 기본값, 기존 수동 영역 마이그레이션, 자동/수동/미사용 전환, 원본 보존, 소유권 검사를 검증합니다.
- 닫힌 옷·목구멍·중앙 무늬·빈 이미지의 오인식 방지와 불투명 안감·밝은 원단·여러 해상도를 테스트합니다.
- 합성 인물과 생성된 열린 봄버·데님 재킷·트렌치코트로 실제 GPU 처리와 로컬/공개 화면을 검증합니다. 개인 사진을 테스트에 사용하지 않습니다.
- 로그·합성 검증 이미지·화면·보존 대조 자료는 Git 제외 경로 `.demo/auto-opening/`에 둡니다.
- `.env` 직접·간접 접근을 금지하고 `FITJANG_SKIP_DOTENV=1`과 audit hook을 적용합니다. 기존 운영 스키마와 파일을 초기화하지 않습니다.
